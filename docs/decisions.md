# Shopflow decisions

## Day 1

| Decision                                                                           | Reason and alternative                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep npm, the existing lockfile, and the installed React, Vite and ESLint versions | Keep the known foundation and add only Day 1 dependencies. Changing package managers or upgrading the app stack would increase the scope.                                                                                                                                                                                                                                                           |
| Use Tailwind 4.3.5 and its Vite plugin                                             | Semantic tokens live in CSS and the app uses utility classes on native elements. A separate PostCSS pipeline would duplicate Vite integration. See the [Tailwind Vite setup](https://tailwindcss.com/docs/installation/using-vite).                                                                                                                                                                 |
| Use TypeScript 5.9 and type-aware ESLint alongside Prettier                        | TypeScript checks app contracts, ESLint catches unsafe use and hooks mistakes, and Prettier handles layout. Syntax-only lint rules cannot catch unsafe use of values from JSON. See [typescript-eslint dependency compatibility](https://typescript-eslint.io/users/dependency-versions/).                                                                                                          |
| Keep both whole-repo and app lint commands                                         | The whole-repo command keeps reporting the existing exercise findings. The app command verifies Day 1 in isolation while preserving the exercises as written.                                                                                                                                                                                                                                       |
| Use native fetch with Zod                                                          | One client owns transport and maps responses to validated types and safe errors. A separate HTTP library is unnecessary for the six operations.                                                                                                                                                                                                                                                     |
| Use MSW in the browser and in tests                                                | Shared handlers exercise HTTP statuses, headers, cancellation and malformed responses. Stubbed client calls would bypass those boundaries. Vitest runs the integration suite and Testing Library checks the shell through accessible roles and keyboard interaction. See [MSW browser integration](https://mswjs.io/guides/integrations/browser) and the [Vitest guide](https://vitest.dev/guide/). |
| Keep mock auth in memory and store only order records in tab session storage       | Reload requires a fresh fake login while the mock can still recognize a repeated order key. An entirely in-memory ledger would forget prior submissions on reload.                                                                                                                                                                                                                                  |
| Use the plan’s local mock assumptions                                              | Contract gaps are documented in the [API contract](api-contract.md), including paging, filters, fake login, order state, idempotency, and test scenarios. A shared authoritative contract would take precedence.                                                                                                                                                                                    |
