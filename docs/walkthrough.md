# Ten-minute Shopflow walkthrough

Before presenting, start the development server with mocks enabled. Use the demo account from the [README](../README.md). Start in a fresh browser session so prior demo orders do not affect stock.

| Time       | Show and explain                                                                                                                                                                                                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–1:00  | Introduce Shopflow and The Bug Bazaar. Point out the catalog, URL filters, and stock counts.                                                                                                                                                                                                                                    |
| 1:00–2:30  | Search for Developer Coffee 0001, open its detail page, add it, open the cart, and update the quantity to two. Refresh the cart to show persistence.                                                                                                                                                                            |
| 2:30–4:00  | Select Checkout, sign in, and show the protected return to checkout. Place the order and open confirmation.                                                                                                                                                                                                                     |
| 4:00–5:30  | Use the [architecture diagram](ARCHITECTURE.md) to explain why the URL owns applied filters, Redux owns cart and session, and Query owns fetched inventory.                                                                                                                                                                     |
| 5:30–7:30  | Explain the actual logout redirect bug. The sign-out handler and route guard both tried to navigate. The test exposed that conflict, and the fix let the guard own the redirect. Show logout from confirmation, then point to [AuthPages.tsx](../src/features/auth/AuthPages.tsx) and [buy.test.tsx](../src/test/buy.test.tsx). |
| 7:30–9:00  | Explain the trade-off. A tab-scoped ledger and memory-only auth keep this demo simple and require sign-in after reload. A production order service would need durable identity and worker records. Point to [orders](orders.md).                                                                                                |
| 9:00–10:00 | Show local test and audit evidence. Identify pending screen-reader, peer and GitHub verification.                                                                                                                                                                                                                               |

If asked about retry safety, run `npm run test:run -- src/test/buy.test.tsx -t "lost response"`. The test forces an accepted order to lose its reply and verifies replay after reload.
